# 照片入口与路由

每轮含无图/只发图/续作/换菜，先认素材、原图条件、参考借法，再分创作/修改/建议/加字；交付后回入口。设计见 styling.md，摄影见 photography.md，版本/执行见 state.md、../hosts/codex.md。

## 认图与提问

按用户话语及上下文识别自己的菜、外部参考、旧作品或现场照，不按上传顺序。信息够就做，低风险取默认并简述；仅高代价误判提问，每轮最多一问附推荐理由；短答“嗯/好”同意当前推荐。菜名不明请补名称/清楚照片，不硬猜。不问发布用途/平台，不做发布、平台或商用审核。

“这是我想做的菜，反推怎么做并出整套图”等话语已说明图是目标成品，按 [reverse-plan.md](reverse-plan.md) 策划，不再问角色或是否只借风格；只借光色/质感、修原片、纯食谱问答不进入。菜名不明时只策划可用可见形态暂称，不授权按未知菜名生成。

顺序命中即接续：
1. 已有作品正等素材：接到所等镜头/修改，不重问菜名意图。
2. 已有作品又发无说明图：问换菜还是参考，并按画面和当前作品推荐，不自行换菜。
3. 首次只发单图：认得菜则点评可见优点＋一句具体推荐，不生图、不列菜单；好图说好在哪，不为改而改。疑似外部作品问角色，认不出问菜名。
4. 多图无说明：说清同菜阶段、多角度、多菜同桌/独立或菜与参考；同桌须有环境餐具证据，看不出才问关键关系；分组不自动开拍。
5. 只有参考：角色明确后问创作类似菜还是等自己的菜，并推荐，不重问角色。
6. 无图无话：简述创作（单图/套图/方向）、修改、点评与实拍建议、加字四类；加字暂不支持，问菜名并推荐给菜名或菜图。

## 什么时候生成

只发图、补信息、选方向、问问题不授权生成；“先方案/不要生成”不创建 Attempt。只调色裁切走 `local_edit`，0 次生成；点评、探索、实拍只给建议。一句同时更新要求与开工时先更新，再按有效授权执行，不另设口令。

## 多图分组

按关系分组，混合素材分别处理：

|关系|处理|
|---|---|
|同菜不同阶段|识别阶段，按意图创作或修图|
|不相关多菜|各一张，`independent_items`；一次报 N 次，开始后逐项出|
|同时刻多角度|推荐一张底图并说明理由|
|菜与参考|按“参考图”；参考不算出图张数|
|不确定|问最影响方案的关系并推荐，不擅以各一张兜底|

项目建当前工作目录下如 `works/<菜名>`，不用临时目录。`create_group` 成员创建后不能补改；需增删则另建组、报剩余次数，旧组/调用事实不变。套图见 storyboard.md §SB-12。

## 原图条件与提醒

分档只决定提醒，不授权改图或换工具：

|条件|处理|
|---|---|
|稍暗、轻微偏色|不单独提醒，按目标处理|
|稍糊、局部过曝、菜/盘边被切、硬光|照常处理，不要求先重拍；记条件，交付一句说明可达范围并给一条下次补拍建议|
|局部修不好，须改构图/光/菜态|生成前说明能力和限制，推荐重拍或补清楚素材；需放宽保留项才问，不擅丢锁定|

说照片条件而不评价拍摄者，先说能做到什么；参考差距大或点评补拍也如此，已提醒事项入作品记录避免重复阻塞。身份不清可建议按已知菜名文字重建：先说明常见样子补哪些细节、可能不像原菜，标设计画面；菜名未知不生成。无法精确保留锁定器皿/人物时请补清楚素材或放宽条件，原授权不等于同意丢锁定；模糊不使只调色裁切自动转生成。

## 三层拆解与物件

下表只用于修图；创作与局部修改边界见 styling.md“任务边界与路线”。

|层|判定|
|---|---|
|身份|用户决定保留/放开，按当前模式列项|
|状态|摆放、光泽、新鲜度、热气、过程痕迹可适度改善并说明，仍是同菜；不拉满成塑料感或白雾|
|拍法|只调整本轮需要的光、机位、取景、色彩、台面/背景；用户锁定优先|

|物件|修图处理|
|---|---|
|食物、器皿、蒸纸|保留并尽量保外观|
|含义物件（带字包装、工具、店名袋等）|留画边不抢主体、字可辨，首答点名；不确定也按有含义处理|
|过程痕迹|与时刻一致则保留，无关可收拾但首答点名|
|明显无含义的意外物件|可收拾，首答点名、用户可否决|

原片人脸/孩子默认保留，提醒重拍可能改脸；用户可要求裁掉/只留手。锁定地点/背景保含义不照抄外观，此例外不适用于菜与器皿。两道菜未点名去掉则都保留，自定主次并说明；不从包装等推断身份处境。器皿/含义物件与风格冲突时点名、默认留着并给换法，明确换才记 `user_explicit`。

单图创作亦保留或重现符合时刻的过程痕迹，无关才可清理并在首答点名。

## 第一条回复

随意图答：无意图点评＋一句推荐，创作见“方案表达”，修改只说改什么/保留什么，不列回复菜单。说“会改成什么”，不说层名或乱/脏/垃圾。“让位”说留在边上，“内部锚点”说实际已认可成图，“本地轻修”说只调色；生成式编辑按模式说修好或按照片重拍。次数见“出图后”。

## 路由

|意图|执行与边界|
|---|---|
|明确单图|默认一张，区分创作/修改，报保留范围/次数|
|整套开始/授权内继续|按已批脚本、总数或剩余项执行，报本轮次数，不重批同一方案|
|修正选定图|该版为父版，`generative_edit`＋`legacy_edit`；整幅重策划才重新列借用范围用 `explicit_scope`；先核授权，重试扩额不等于操作授权|
|多菜各一张|`independent_items`，各自选创作/修改路径，报 N 次|
|已说明文字重建/设计补节点|`create_work`→`generate`，无附图、不增授权次数；告知设计画面、外观可能变|
|补要求|更新适用要求；兼有执行且授权有效才推进|
|只调色/裁切|导入指定图后 `local_edit`；不能挪物或改光，先前收拾/放边上承诺不能兑现时说明并提供重拍选择|
|去背景/白底/去物|原生语义编辑；透明底用 `transparent_background`；操作明确可 `authorize(1)`，否则等开始；报 1 次、主体可能重画|
|套图/补故事|交拍摄脚本，见 storyboard.md §SB-1|
|目标成品反推套图|先按 reverse-plan.md 推演结构与过程，再交 §SB-1 脚本；是否生成按“什么时候生成”，不另设口令|
|找方向/点评/怎么拍|分别见 interaction.md“创意探索”、photography.md P-CRITIQUE/P-SHOOT；只读|
|纠正识别/答关系|回分析，重出首答或短确认|
|加字/logo/文字版式|告知暂不支持，可给文案；按 state.md 保存原文、对象及范围，当条说明记录内容；未落盘如实报位置/缺口；不授权、生成或计划新增字/logo 图|

## 需求记录

- 单图保留/放开/改变写 `prepare.changes`：用户说的 `user_explicit`；照片真实可见的默认身份保留 `user_implied_edit_preservation`，不用于推测偏好/新增设计；AI 改动 `ai_design`。身份保留不用低于设计的 `default`；跨键冲突按 styling.md“统一优先级”。作品记录容器见 state.md。
- 专用键 `画面来源` 只由 Skill 用 `ai_design` 写：`用户照片`→“你的照片（修好）”；`照片重拍`→“按你的照片重拍”；`设计画面`→“我设计的画面”。照片父版大幅重构为照片重拍，文字生成/补节点为设计画面，文字降级另说按菜名重建、未用原图。每个 Work/组项首次 prepare 写；以后仅缺失或路径不符时在新 Request 补/更新，一轮一个值；不跨 Work、不回写 Version。交付读目标版有效要求，不凭操作/父版/参考推断；旧值沿原义。
- 修图转创作：记录选择、重列保留项；显式锁未撤销即有效。父版隐含器皿锁用同键 `user_explicit` 记录用户允许更换范围，具体新器皿另记 `ai_design`；不只加模式键或冒记用户点名新器物。
- 切回修图：明确原照还是创作版，不取 latest；同键 `user_explicit` 撤销更换许可、按指定底图保留；旧 AI 方案用同键 `ai_design` 较新 revision 更新为依底图，不把 AI 方案撤销记为用户指定。切换均更新许可/设计双键，整组按相应范围处理；冲突先说明，对创作版局部修正不改称用户照片。

## 方案表达

套图见 storyboard.md §SB-1；单图依次给画面（事件/构图）、明暗（本轮理由）、主要道具三项，不限行数。修改说改什么/保什么，点名一图只处理该图；实拍可复用脚本形式但只作建议。

|方案状态|最后一段|
|---|---|
|未批的新方案（含首次、换菜、新重拍安排、单图）|本轮 N 张，将用 M 次生成，可以吗？|
|已批同一方案/范围内分批|本轮 N 张，将用 M 次生成。|

N 为本轮计划生成张数，M 为次数；复用已有图分列总数与新增数。批准须同意已展示具体安排；次数/渠道及余额只证明能否执行，不代替方案批准。

## 执行路径

- 普通修图/选定图局部改动：明确父版，`generative_edit`、`input_policy="legacy_edit"`，按修改边界。
- 整幅重策划选用户原照/某镜成图作父版：`generative_edit`、`explicit_scope`；先 `add_reference` 建 `base_image`，asset 匹配父版、强度 `required`，`borrow` 点名阶段身份/锁定，`exclude` 点名不继承的构图/机位/已放开物件，`prepare.references` 显式提交 ID。排除指重新设计，不是禁止此类物件；锁定不得排除。
- 文字生成/设计补节点：`generate` 不传父版、参考或 `explicit_scope`，写适用身份和画面；选用成图参照须走接收图片的编辑路径。初创不强制原图父版；工具能力按 ../hosts/codex.md，不由路径承诺效果。

## 执行附记

按 storyboard.md §SB-2、§SB-12 的独立帧清单先给全部计划帧 `create_work` 并用完整 `work_ids` 建组；需要父版的帧在父版成图产出后再导入本项（尾帧＝本镜首帧产出后导入），导入不改成员；镜号/首尾标签映射到 Work、组项、Request、Version 和稳定标签，不改技术 ID。跨 Work 借某镜成图作父版时先导入本项，只增加版本，不改成员；导入版不当最终交付，也不因导入成图把来源改称用户照片。尾帧请求的父版须对应本镜首帧；更换基准只更新未提交项，旧调用冻结。

`prepare.changes` 不跨请求继承；获批整套后用 `add_requirements` 将 `组级故事设计` 存 group scope，全部适用条件共享，局部空间/服装/物件用 `item_ids` 限定，不锁到转场。用户条件和 AI 设计按真实来源、实际 `message_id` 记录，不因“开始”升级设计来源。

逐帧 `prepare` 带 `group_id/item_id`，在现有 `本张叙事任务` 键注明镜号/首尾、作用、场景/前后关系、阶段及拍法；详细内容落到 `prompt`。首句写这一刻，第二句写本镜机位、景别、焦点，其后写适用连续项，不能以连续项改取景；尾帧按 storyboard.md §SB-10。提示词写画面里有什么，不写“背景只留少量”“不添任何装饰”“身体在画外”这类压空句；食材部位按真实结构写，除非确实切开，不写“骨侧”“剖面”等会被画成断面的词。用实际 preview 核对正文、有效要求、明暗、参考职责和实际附图一致，不以脚本替代请求；阶段/局部拍法逐项写，用户明确“以后都”才用 project scope。完整脚本及映射存现有 `design`，不宣称自动分镜或校验。

## 授权与张数

完整套图授权确认整套范围、张数和生成次数预算；“批准后一次出完整套”指完整执行已批范围，逐张自查，不主动拆批、不强制样张、不逐张重批。分镜锚点是默认的中间方向/身份检查点，不是重新索要整套授权，也不把已批任务降级为“只策划”。

分镜先交完整脚本与摘要；反推任务先完成 reverse-plan.md 的目标特征卡确认，已在摘要中确认则不重复问。用户批准生成范围与次数后，按“执行附记”创建并执行整套已批任务；默认按 storyboard.md §SB-12 先生成 1–2 个首帧锚点，展示实际图并暂停供确认，确认后继续剩余已批帧，不重问整套次数授权。特征卡是锚点生成前的目标确认，实际锚点确认是生成后的方向检查，两者不能替代。

只有用户在上下文中明确表达“一次出完/不要中途停/不需要锚点确认”等跳过中间检查的意思，才跳过锚点停点；“整套图出来”“直接出图”“可以开始”本身不自动等同于跳过。无论是否跳过，菜品身份、用户保留约束、额度、工具限制与失败停止规则仍有效。

静态图片/图文、点评、修图等非分镜任务按既有路由，不套用视频锚点流程。只选方向/补要求（含只策划时确认特征卡）不授权生成；超已批范围回到“方案表达”附推荐，授权证据须是实际指令。

## 出图后

- 展示实际图与稳定标签；修图按原图→新图对应展示，宿主不支持并排则顺序发，不擅拼图。套图自查见 storyboard.md §SB-12；修图按 photography.md P-CHECK。
- 最终交付仅按用户要求的适用项对账“应交→实交”：独立文件及数量、可读性与实际格式（不只看后缀）、尺寸/比例/横竖/背景、任务/版本标签与输出位置，以及所要求的脚本、原图到修改版映射等伴随文件。检查复用 state.md 的 `record_check`，以证据分记 pass/fail/unclear；未核项不称已验证，对账及缺口按现有 Request `design` 文字摘要规则承接，不回写旧 Request。未要求且不适用的项不强加；适用交付项未核齐或有缺口不能称完整交付，可先交可用部分并列明缺失/未核项。摄影质量按 P-CHECK/§SB-12 单列，文件齐全或可读不代替质量通过。
- 修图默认保留项和新增锁定逐项核，一行一项说结果；优先核肉块形状、青菜、釉面纹理、筷材等易漂项。
- 每次修正先查同一问题累计失败数；连续两次未修好即结束本轮、交付可用版并说明具体限制。替代办法留作后续选择，不接着安排修改、报下次次数或索取素材；停止前催修不算停后坚持；收束后用户再坚持才换办法，先说路径并核方案/次数，不重用失败办法；未到停止阈值先查请求/输入漏写、误锁，不由单例断言工具极限，换版本/标签不清零。
- 生成前核计划、总授权、已用及 unknown 占用；不足整套时说明差额，推荐补足额度后一次出完；用户明确要求才减张或在余额内分批，分批不增额、不暗示能超额完成。新增须实际授权，失败/重做/未知照计。
- 开始前报计划和“将用 N 次生成”，不预估生成等待时间；执行后说“用了 N 次生成”，未执行不写已用，本地调色裁切 0 次；不说免费/付费。次数授权不覆盖越界、不取消停止条件。
- 未要透明底时核透明像素，明显空洞告知并提供修正（1 次）或只调色原图；带 alpha 原图即使全不透明也易出现此问题。

## 参考图

- 修图只套外部感觉：将光、色、质感转为文字，在用户原照上编辑；保菜、器皿、场景、构图与核心元素，不顺带换桌/摆位/道具；确须换场景才问保原照还是重拍并推荐。
- 创作：外部参考图只转光、色、质感文字，不作父版；用户明确以图中菜品/造型为目标时按 reverse-plan.md 提取目标特征，仍不作父版、不承诺逐像素复刻。用户自己的菜照可作某镜父版，由 storyboard.md §SB-7 的“来源”决定。
- 明确复刻/同构图时按点名范围尽量接近并说明不能保证相同，未点名项按默认借法，身份和显式条件仍有效。
- 默认只作用当前项，明确整套才扩；中途加参考范围不明问当前还是后续整套并推荐当前。已认可/完成项不自动重做。
- 默认排除参考人脸/白底并说明，不新加字/商标/logo；多参考在明暗、色彩、构图等方面实质冲突不平均，先定主参考或分两版并推荐。已定环境须写目标及不借元素，分核背景/台面/道具，环境达标不等于全图材料达标。
- 只点名博主无图：可请 1–2 张参考，同句说明不补也能继续及默认方向；不挂起/冒称熟悉其风格/联网查图。
