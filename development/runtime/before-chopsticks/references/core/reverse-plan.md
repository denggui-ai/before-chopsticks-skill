# 从目标成品推演图片脚本

适用于用户以图片或描述指定想做出的菜品/造型，并要制作过程、整套图片或分镜。只借光色、修原片、纯食谱问答不进入；用户没有要求过程的成品组图也不强加过程。

## 先确定目标及依据

按用户明确借用范围识别食物、造型和摄影三层。列出影响结果的少量关键特征：材质与食材形态、相对位置和高低、支撑/叠压、液体区域与留白、器皿和整体光色。用户换菜或只借部分时重算其余条件，不沿用原食材的物性与做法。把目标特征写成一张特征卡（整体轮廓与比例、主次部件及姿态、关键食材可见外观及易被画错成什么、光色），作为一页摘要的第一项请用户确认；成品锚点按确认后的特征卡写提示词，出图后逐项对照。

区分图中可见、候选推测、为本次新增的设计。单张成品不能证明原作者的配方、隐藏支撑、工序顺序、器材或图像制作方式。雾、悬浮、异常高叠等先作为画面现象；不能据此断定原图由 AI 生成，也不能当成已证实的实拍工序。

菜名或材料不明时可用形态暂称继续拆造型；只在未知项会改变关键路径时提出一个必要问题，或明确给条件方案。进入实际生成仍遵守 intake.md 的菜身份与授权条件。

## 倒推形成，再正向核对

从每个关键成品特征追溯：需要的前置状态 → 动作及作用位置 → 所用食材/工具 → 可见结果。按关键材料记状态变化与汇合点，把食物熟化、造型组装、摄影效果分开，再按依赖连接；呈现次序可以另作叙事安排。备料镜不提前出现成品才有的状态。

烹制优先采用用户提供的做法；没有时选择一条合理候选并明说依据和不确定性，不冒称还原唯一原工艺，不从色泽补出精确时间、温度、配方。若关键连接仍不明，脚本对应镜继续保留条件或待核实标记，不能仅开头免责声明、正文却写成确定事实。

对高叠、弯折、承托和液体形状，检查食材形态、重力、接触与容器是否支持动作。疑难处给可解释的实现假设、较可行的替代及对目标的偏差，或保留待验证节点，不凭空补一个“摆好”跨过去；新增承托材料标为设计假设。用户明确幻想创作时允许设计性变化，但标清视觉设定，仍交代画面前后因果，不把它包装成实拍教程。

造型摆盘（多部件立体造型或留空构图）先写摆盘设计，再倒推加工：① 按部件列材料、姿态、可见单元数（给范围；可见单元不等于食材件数）、尺寸与朝向，无尺度参照先设盘径；② 每个立体件写重量落点与支撑，看不见的芯是设计假设并给替代，实际做法与照片不同（如分片拼接代替整片弯折）须写明；③ 河道、留白等空白从第一步预留，写清边界靠什么形成；④ 摆盘顺序：难调整、难伸手的先做，起遮挡作用的后做，液体、点缀与易变效果最后，在拍摄位完成，每步写工具；⑤ 按部件姿态倒推切配规格与加工状态（冷热、干湿、稠度），上盘量与准备量分开（含挑选与失败备用），据此定采购与烹饪；⑥ 雾、反光线条、微缩装饰等画面效果单列可做、替代或省略。

将链条正向走一遍：所需食材/工具有来处；熟化、切分、组装的顺序不互相冲突；关键结构逐步形成；后续动作不会无说明地毁掉已成结构。图里看不到或尚未验证的支撑不能宣称已经可靠。

## 进入脚本

以目标最有辨识度的形成动作确定重点。每张/镜只交代可读的主变化，关键步骤有前态、动作与后态；删掉某镜会失去哪项关键解释，用来辨别重复，不用来压张数。一般准备过程按故事需要取舍，不强制采购、家庭故事或固定镜数；人物、环境与机位仍按 storyboard.md §SB-3、§SB-4、§SB-8、§SB-9，不把整套裁成贴着食材的步骤图。造型摆盘按部件成镜，不压成几镜“摆好”；备料镜体现规格分级与数量。

连续条件按阶段写：目标的空间关系主要约束摆盘与成品段；前期只继承仍适用的食材、器物、人物等，不把最终造型锁进备料镜。交付类型按 storyboard.md §SB-1：明说静态才交静态，只说“整套图片”按默认并一句说明可改静态，不因进入反推而改默认。

交付前逐项核对：关键目标是否在最终镜保留；其形成动作是否真的进入逐镜脚本；推测是否在相关镜保持限定；转换是否有可见依据。缺口具体写在受影响镜，脚本通过只代表文字逻辑检查，不代表厨艺可复现、真实成图连续或视频效果已验证。是否生成按 intake.md“什么时候生成”；明确先方案/不生图时到脚本为止。
