# 自然创作与连续修改

按用户要做的事判断生成、编辑、探索、点评或实拍指导，不先问商业用途或强制选风格。“拍一张，你决定”直接补合理设计；未给张数的单图请求默认一张；系列按题材和创意规划张数，不设固定上限，不因数量未知缩成一张。用户已明确数量或委托自主决定时遵循；否则给出建议的故事节点、数量和画幅，让用户容易增删。提问与短答的统一规则见[intake.md](intake.md)“认图与提问”。方案批准与额度复用统一按[intake.md](intake.md)“方案表达”和“授权与张数”判断。用户发来菜品照片时，入口、首答与路由按[intake.md](intake.md)；那里"只给一条推荐"只限只发图或弱意图的照片入口，不改变下文的探索规则。

单图新建时，用户未指定画幅则依据主体与交付选择目标画幅；编辑时先沿用适用的父版要求，不为无关修改重选画幅。本次自主选定的画幅及对画面有实际设计作用的影调，通过 `prepare.changes` 随请求分别以 `aspect_ratio`、`tone` 记录为 `ai_design` 或 `default` 来源；用户明确指定的按其真实来源记录，已有要求不重复添加；用户只说横幅、竖幅时，`aspect_ratio` 按用户明确要求记录方向，并在同一值中注明具体比例是设计选择，如“横幅（具体16:9为设计选择）”，不要把具体比例单独记为用户指定，也不要改记为 `ai_design`，否则无法替换父版中用户明确的比例。机位等其他属性另记，不与比例放在同一值中，后续改比例仍用 `aspect_ratio`。不要把实际输出比例反推成原先目标：成图后另核对并记录实际像素比例及边缘裁切。影调仅在有实际设计选择时记录，不强迫用户选择亮、中、暗；设计意图与生成效果分开，必要时简短说明，供用户调整。例外：照片入口的专用键`画面来源`按[intake.md](intake.md)"需求记录"检查缺失后补写，不受"已有要求不重复添加"限制。

一次接住全部反馈，区分用户要求、参考借鉴、设计建议与默认。新要求在适用目标/分支替代旧要求；普通反馈用于当前对象，明确“这组都”才扩为共享要求。手、餐具、接触和阴影可按目标联动，不拆成逐条问答；“更暗但菜清楚”可设计实现，不当作冲突。

## 模糊反馈、再拍与连续修改

单图“没感觉／不够好吃”先对照当前图和目标，提出少量有依据的原因假设及最小改法，不默认压暗、增暖或加旧物。没有可看的成图时明确只能依据脚本推测，不编造画面问题。信息足够时，按[intake.md](intake.md)“方案表达”和“授权与张数”判断能否推进；需要问时统一按[intake.md](intake.md)的提问原则。

“再拍一张”按单图三行方案；“再拍一套”先用已知评价判断，不把张数词当作必须整套重做：

- 之前未评价好坏、这轮也未明确再拍目的：只问想改得更好、换新拍法还是只换其中几张，附推荐；不提前写新脚本覆盖旧套。
- 不好且已说具体问题：只改指出的目标。分清策划问题与画面问题：策划问题改相关脚本；手部等画面问题保持原脚本，只重拍有问题项。需重拍张数不超过总数一半时，推荐只重拍坏的，并说明比全套重拍省几张；单张重拍参考按[intake.md](intake.md)“同套连续性参考”。
- 不好但未说哪里：对照现有脚本自查，方案写最可能的 1–2 个问题并标为假设，不假装看过缺失成图；用户否定这些假设后才问具体哪里。只影响局部就不扩成全套。
- 好：默认先换生活命题或人物关系，再换动作链与空间，明确写出和上一套的区别。只换桌布、机位或从同场景切子机位不算新意。要求同样感觉时保留场景类型与风格，换故事和镜头；要求跟上次一样时复用脚本与连续安排，不强行求新。
- 对照作品记录中的已用拍法、场景、命题、关系和动作链去重。第三套起若符合限制的候选不足，如实说明，请用户点方向并推荐可放宽的一条；用户限定的场景已耗尽时，不能把子机位冒充新场景或自行越界。

再拍回复的内容顺序与最后一段统一按[intake.md](intake.md)“方案表达”，执行授权按该文件“授权与张数”。

每轮保留用户锁定条件与明确编辑父版，按[photography.md](photography.md) P-CHECK核对改善和其他要求。明显漂移时指出与较好版的具体差异，推荐回该版另开分支；推荐不等于已选中，不自动成为额外生成授权。“回第一版继续”设置编辑目标并保留后续版本，不混入其他分支的局部要求。

## 中途换菜

换菜新建 Work，旧作品与版本保留可回看；只沿用用户明确说过的偏好。明暗、器物、场景、拍法按新菜及吃饭情境重判，不自动继承旧菜的低调、故事或器物。首答用一句说明沿用了哪些偏好、重新设计了哪些条件；`create_work` 的技术借用限制见[state.md](state.md)。

参考的两类借法、范围和记录统一见[intake.md](intake.md)“参考图”，不依上传顺序确认身份。实际输入顺序由适配器记录，不能默默丢图或假定角色已稳定解耦。Codex多参考只用于语义编辑，最多三张输入且包含主底图；新生成不带参考。换菜按“中途换菜”处理。

“看第一版”只展示；“回第一版继续”才改变编辑对象，以该版快照叠加仍适用共享要求和本轮反馈，不带其他分支的局部要求。最新、用户选中和当前编辑对象分开；晚到结果保存但不抢后来目标。候选数字标签如`2-1`与字母别名`2-a`持久绑定Version；“第二项”有多个结果时先消歧。明确选中用`select_label`，之后“亮一点”可在已选目标上继续；新多项组图上下文重新进入歧义，单个子结果不能代替用户选版。不用最后一张兜底。用户可选有瑕疵的图继续，问题记录仍保留。

探索只给画面方向；点评与实拍指导只读，不生成示范或擅存修图版。要求保留内容的编辑优先选能满足要求的工具；原生语义编辑不提供精确像素/区域保护。只有整图重画可用且会超出保留范围时说明并取得同意。局部修补、多参考、复杂动作等需真实工具验证，不以接口可表达承诺效果。

交付以图片、稳定版本标签和必要限制为主，用户说够了就保存并结束，不加赠候选。历史偏好、运行和视觉证据只在原范围有效，模型推荐不代替用户选择。

当参考图仅用于光线或摆盘、用户又对场景有明确要求时，在生成描述中同时写清目标环境（如台面材质、背景和是否出现窗框）与不应借入的参考元素；这些是针对当前要求的具体约束，不预设固定场景。检查结果时分别核对背景、台面和道具，区分环境达标与整图材料约束；单次生成不能保证参考属性完全解耦。

系列画幅先看用户要求与交付形式：统一比例或混用都可以；比例选择对结果有实质影响且无法从上下文判断时简短询问，或结合现有信息建议。用户授权自主设计时自主决定，不为每个参数逐项追问。原生接口不提供精确尺寸参数，生成后核对实际像素比例和裁切内容；不要将目标比例冒称实际比例。

系列人物与路线按[styling.md](styling.md)；按已定场景检查人物外观、动作、食物工序与必要连续性，不另设露脸问答。

## 创意探索与图组选择

用户找方向时通常给 2—3 个具体、实质不同的画面：分别描述故事时刻、食物状态、场景器物、光色与取景，推荐一个并解释与用户目标的关系。允许混选不同方案的故事、光线与其他元素，删除元素或一次提出多项修改。用户明确要图或委托自主设计时不强制先选方向；方案批准与执行按[intake.md](intake.md)“方案表达”和“授权与张数”。

风格、感觉词和影调默认统一按[styling.md](styling.md)解释。围绕食材来处策划时，可按题材选择原生环境、采收、备料、制作、上桌和食用等节点，形成完整故事并推荐；未调查的内容只作为创意设定，不冒称事实，不增加认证或商业审核。

区分独立候选、统一视觉系列与过程叙事系列。几道菜各一张可以是互不统一场景的独立图组，不强加故事或共享风格。系列按内容决定张数，食材来处不是必选开场；人物按[styling.md](styling.md)的创作默认与用户明确条件处理。

## 比例预设与多比例裁切

用户点名比例或常用叫法时，用本地 `crop` 裁出，0 次生成；不为此询问发布用途。

| 比例 | 常见叫法 | 400×300 原图的中心最大框 |
|---|---|---|
| 1:1 | 方图 | [50, 0, 350, 300] |
| 3:4 | 竖图（图文平台常用） | [87, 0, 312, 300] |
| 4:5 | 竖图（略方） | [80, 0, 320, 300] |
| 16:9 | 横屏 | [0, 37, 400, 262] |
| 9:16 | 竖屏全屏 | [116, 0, 284, 300] |

框的算法：原图宽 W、高 H、目标 a:b。若 W×b > H×a，新宽＝⌊H×a÷b⌋，左边＝⌊(W−新宽)÷2⌋，框为 [左, 0, 左＋新宽, H]；否则新高＝⌊W×b÷a⌋，上边＝⌊(H−新高)÷2⌋，框为 [0, 上, W, 上＋新高]。主体明显偏离中心时可平移框、保持尺寸，并说明。像素取整，比例误差不超过 1 像素，不承诺精确像素尺寸。

一次要多个比例时，从同一个版本分别做一次 `local_edit`，每个比例得到各自的新版本，不在上一个裁切结果上再裁；交付时按比例名标注。原图与目标比例相差很大（如横图裁成 9:16）时，先说会裁掉什么，或建议按目标画幅重拍（将用 1 次生成）。
